# 로블록스 트렌드 트래커 v2

3시간마다 로블록스 홈 화면의 정렬 목록(Top Trending, Up-and-Coming 등)과 게임별 동접·방문수를 기록하고, 매일 아침 전날 하루치를 이전 날들과 비교한 리포트를 디스코드로 보내요. GitHub Actions에서 무료로 돌아가서 PC를 켜둘 필요가 없어요.

## 리포트에 나오는 것

| 섹션 | 내용 |
|---|---|
| 🔥 Top Trending / Up-and-Coming 상위 10 | 오늘 아침 기준 순위와 어제 아침 대비 변동(▲▼, NEW) |
| 🇰🇷 한국·모바일에서만 상위권 | 한국 기준 목록에는 상위인데 전체 목록에는 없는 게임. 확인해 보니 로블록스는 기기 설정을 순위에 반영하지 않아서, 이 차이는 순수하게 국가 차이예요 |
| 🚀 급상승 TOP 10 | 하루 방문 증가량(없으면 평균 동접)이 **2일 이상 연속 상승**하고 약 3일 전보다 1.3배 넘게 오른 게임. 8일째부터 지난주 같은 요일 대비 배수도 표시 |
| 🆕 처음 차트에 등장 | 전날 처음으로 정렬 목록에 오른 게임. 출시 90일 이내 신작을 먼저 보여줘요 |
| 🐣 신작 레이더 | 출시 60일 이내인데 차트에 오른 게임 |
| 👤 개인 계정으로 올린 신작 | 출시 90일 이내, 그룹이 아닌 개인 계정 소유인데 차트에 오른 게임. 1인 개발 가능성이 높은 참고 사례 |
| 🧬 클론 신호 | 출시 90일 이내 게임 3개 이상의 이름에 겹치는 키워드(예: `ragdoll`). simulator·tower·tycoon 같은 장르 단어는 제외하고, 평균 출시일과 1주 전 대비 개수 변화를 표시 |
| 💵 매출 순위 변화 | Top Earning 상위 50위 안에서 **변화가 있을 때만**: 지난 7일간 50위 밖이었다가 새로 진입, 전날보다 10계단 이상 급등, 출시 90일 이내 신작 |
| 📅 주간 매출 상위 10 | 매주 월요일 아침(일요일 기준) 리포트에만. 1주 전 대비 순위 변동, 동접 순위에 비해 매출 순위가 훨씬 높은 "수익 효율" 게임, 그 게임들과 매출 상위 신작의 게임패스 구성(개수·가격대) |

표시 기호 (게임 이름 뒤에 붙는 태그)
- 👍94%: 좋아요 비율
- ⭐1.2%: 방문 대비 즐겨찾기 증가율. "다시 오고 싶은 게임"인지 보는 지표
- 🔁재방문12위: 로블록스 Top Revisited(재방문 많은 게임) 차트 순위. 잔존율이 좋다는 신호
- 🛠업뎃 2일 전: 최근 3일 안에 업데이트됨. 급상승이 업데이트 효과일 수 있음
- 👤개인 계정 / 👥그룹 소유: 게임을 어느 계정 이름으로 올렸는지예요. 실제 개발 인원과는 다를 수 있어요(혼자서도 그룹으로 올리는 경우가 흔하고, 개인 계정 게임도 협업자가 있을 수 있음). "(차트 3개)"는 같은 소유자의 게임이 차트에 여러 개 있다는 뜻
- ⚠️ 방문 증가에 비해 동접이 비정상적으로 높은 게임. AFK 보상으로 동접을 부풀렸을 가능성이 있어요.

## 이렇게 동작해요

- **3시간마다 측정:** 하루 8번 재서 하루 평균·최고 동접으로 비교해요. 한 번만 잴 때보다 시간대 흔들림이 훨씬 줄어요.
- **하루 방문 증가량이 주 지표:** 누적 방문수의 차이라서 시간대 영향을 받지 않아요.
- **관심 목록:** 한 번이라도 차트에 오른 게임은 차트에서 빠진 뒤에도 30일간 계속 추적해요. 뜨고 지는 흐름 전체가 기록으로 남아요.
- **리포트는 하루 한 번:** 오전 9시 이후 첫 측정(9시 17분쯤)에서 전날 0시~21시 측정분을 정리해 보내요.

## 세팅 순서 (20~30분)

### 1. 디스코드 웹훅 만들기
1. 리포트 받을 채널의 **톱니바퀴(채널 편집) → 연동 → 웹후크 → 새 웹후크**
2. 이름을 정하고 **웹후크 URL 복사**. 이 주소는 비밀번호처럼 다뤄 주세요.

### 2. GitHub 저장소 만들기
1. github.com → 오른쪽 위 **+** → **New repository**
2. 이름 자유, **Private** 추천, **Add a README file** 체크 후 생성
3. 사용량: 한 번 실행에 2~3분, 하루 8번이면 월 600~700분 정도예요. Private 저장소 무료 한도(월 2,000분) 안이에요. Public 저장소는 무제한이지만 기록이 공개돼요.

### 3. 파일 올리기
1. **Add file → Upload files**로 `trend_tracker.py`와 `README.md`를 올리고 **Commit changes**
2. 워크플로 파일은 직접 만들어요(점으로 시작하는 폴더는 업로드가 잘 안 돼요).
   - **Add file → Create new file**
   - 파일 이름 칸에 `.github/workflows/trend.yml` 입력(슬래시를 치면 폴더가 생겨요)
   - `trend.yml` 내용을 통째로 붙여넣고 **Commit changes**

### 4. 웹훅 주소를 Secret으로 등록
1. 저장소 **Settings → Secrets and variables → Actions → New repository secret**
2. Name: `DISCORD_WEBHOOK_URL` / Secret: 웹후크 URL → **Add secret**

### 5. 첫 실행
1. **Actions** 탭 → (처음이면 활성화 버튼) → **Roblox 트렌드 트래커** → **Run workflow**
2. 수동 실행은 시간과 상관없이 바로 리포트를 보내요. 첫날은 "오늘 지금까지" 기록으로 순위와 신작만 나와요.
3. 이후엔 3시간마다 자동으로 측정하고, 리포트는 매일 오전 9시 17분쯤 와요. GitHub 사정으로 수십 분 늦을 때가 있어요.

## 정확한 시각에 돌리기 (외부 예약, 권장)

GitHub 예약 실행은 무료 저장소에서 자주 늦어지거나 빠져요. 그래서 cron-job.org 같은 무료 서비스가 3시간마다 GitHub에 실행 요청을 보내게 하는 걸 권장해요. GitHub 예약은 백업으로 그대로 두고, 직전 측정이 100분 안에 있으면 자동으로 건너뛰어서 중복 측정은 안 생겨요.

1. **GitHub 토큰 만들기:** 프로필 → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token
   - Repository access: Only select repositories → `roblox-trend-tracker`
   - Permissions → Repository permissions → **Actions: Read and write**
   - 만료 기간을 정하고 생성한 뒤 토큰을 복사해요(다시 볼 수 없어요).
2. **cron-job.org에서 작업 만들기:** 가입 → Create cronjob
   - URL: `https://api.github.com/repos/JsikDown0/roblox-trend-tracker/actions/workflows/trend.yml/dispatches`
   - Schedule: 사용자 지정(Custom), 시간대 Asia/Seoul, 매일 0·3·6·9·12·15·18·21시 17분
   - Advanced → Request method: **POST**
   - Headers:
     - `Authorization`: `Bearer 복사한토큰`
     - `Accept`: `application/vnd.github+json`
     - `Content-Type`: `application/json`
   - Request body: `{"ref":"main","inputs":{"report":"auto"}}`
3. **테스트:** 작업 화면의 Test run(실행) → 응답 코드 **204**면 성공이에요. Actions 탭에 새 실행이 생겨요.
   - 401/403: 토큰이나 권한(Actions: Read and write) 문제
   - 404: URL 오타, 또는 토큰에 이 저장소가 선택되지 않음
   - 422: 본문 오타

Actions 탭의 **Run workflow** 버튼은 `report` 값이 기본 `now`라 누르면 바로 리포트가 와요. 외부 예약은 `auto`라서 오전 9시 이후 첫 측정 때만 하루 한 번 보내요.

## 기록이 쌓이는 속도

| 기간 | 작동하는 것 |
|---|---|
| 1일째 | 순위, 한국·모바일 전용 상위권, 신작 레이더 |
| 2일째 | 순위 변동, 처음 차트 등장 |
| 3~4일째 | 연속 상승 기반 급상승 |
| 8일째~ | 지난주 같은 요일 비교, 1주 기준 클론 신호 |

## 안 될 때

- **Actions가 빨간 X로 실패:** 실행 기록에서 `측정` 단계 로그의 마지막 몇 줄을 복사해서 Claude한테 보여주세요.
- **디스코드에 "⚠️ 트렌드 수집 실패":** 로블록스 응답 구조가 바뀌었거나 일시적으로 막힌 경우예요. 하루 넘게 계속되면 메시지를 보여주세요. 로블록스 웹사이트가 쓰는 비공식 API라서 로블록스가 바꾸면 수정이 필요해요.
- **🇰🇷 섹션이 전체·PC와 늘 똑같거나 비어 있음:** 로블록스가 국가·기기 설정을 반영하지 않는 거예요. 그때는 `VARIANTS`를 `all:computer`만 남기면 돼요.
- **기록 저장에서 push 실패:** Settings → Actions → General → Workflow permissions를 **Read and write permissions**로 바꿔 주세요.

## 설정 바꾸기

`trend.yml`의 `env:` 값을 바꾸면 돼요.

- `REPORT_HOUR`: 리포트 받을 시각(한국 시간). 측정은 0·3·6·9·12·15·18·21시 17분이라, 예를 들어 `12`면 12시 17분쯤 와요.
- `MIN_CCU`: 급상승 후보 최소 평균 동접(기본 300)
- `NEW_GAME_DAYS`: 신작 기준 일수(기본 60)
- `TOP_N`: 섹션별 표시 개수(기본 10)
- `MIN_GAP_MIN`: 직전 측정과 이 분 이내면 측정 건너뜀(기본 100분)
- `WATCH_DAYS`: 차트에서 빠진 뒤 추적 일수(기본 30)
- `EARN_TOP` / `EARN_JUMP`: 매출 순위 감시 범위(기본 50위)와 급등 기준(기본 10계단)
- `WEEKLY_DAY`: 주간 매출 요약 요일(0=월 … 6=일, 기본 6 → 월요일 아침 도착)
- `VARIANTS`: 수집 기준. `국가:기기`를 쉼표로 구분, 첫 번째가 기본이에요.

## 한계

- 로그인하지 않은 상태의 홈 화면 기준이라 실제 개인 화면과는 달라요.
- 정렬마다 최대 100개까지만 보여서, 아직 어떤 목록에도 안 오른 게임은 잡히지 않아요. "뜨기 직전"이 아니라 "차트에 막 올라온 시점"을 잡는 도구예요.
- 클론 신호는 게임 이름 기반이라 이름이 전혀 다른 클론은 못 잡아요. 장르 단어 목록은 `trend_tracker.py`의 `GENRE_WORDS`에서 고칠 수 있어요.
- 과거 기록은 로블록스가 주지 않아서 첫 실행부터 쌓여요. 특정 게임의 예전 흐름은 RoWatcher(무료)나 CCUCheck(일부 무료) 같은 외부 사이트에서 보세요.
- 기록은 하루 수백 KB~1MB 정도 늘어요. 1년이 지나 저장소가 무거워지면 오래된 `data/daily` 파일을 지워도 돼요(최근 8일치만 비교에 써요).
